# 常用接口归并建议

这份文档只做整理建议，不改代码。

## 目标

把高频、重复出现的能力收拢成少数几个公共入口，减少各个 `Command`、`Contribution`、`Utils` 里反复拼脚本、拼参数、拼转换逻辑。

优先归并这几类：

1. 关节运动
2. 直线运动
3. 逆解
4. 摆动及摆动参数填充
5. 四元数 / 欧拉角转换

## 现状分布

| 能力 | 现有位置 | 说明 |
| --- | --- | --- |
| 关节运动 | `task/command/MoveJCommand.java`、部分节点贡献类 | 主要是脚本拼装 |
| 直线运动 | `task/command/MoveLCommand.java`、`MovePCommand.java` | 当前 `MoveLCommand` 实际发的是 `movep()` |
| 圆弧运动 | `task/command/MoveCCommand.java` | 兼顾摆动圆弧、固定圆弧 |
| 逆解 | `utils/InverseKinematicsUtils.java` | 已经有请求串和返回值解析 |
| 摆动模型 | `domain/process/oscllation/*`、`config/conversionstrategy/OscillationConversionStrategy.java` | 参数类型分散在多个类里 |
| 姿态转换 | `domain/math/Math3D.java`、`utils/AngleTransUtils.java`、`utils/PoseCalcUtils.java` | 主要是 RPY / Frame / Transform3D |
| 四元数 | 当前代码里没有独立统一入口 | 需要新增统一转换层时再收口 |

## 建议抽成的公共接口

### 1. 运动脚本接口

建议做一个统一的运动脚本入口，负责生成或下发这些常用运动：

- `moveJ`
- `moveL` / `movep`
- `moveC`
- `speedl`
- `stopl`

建议职责：

- 统一脚本拼接格式
- 统一 `allowableOffset` / `touchSense` 这种前置包装
- 统一 `framePose` 的附加处理
- 统一速度、加速度、blend、sleep 这类参数顺序

建议未来对外暴露成一层类似：

- `RobotMotionApi`
- 或者 `RobotMotionScriptApi`

### 2. 逆解与正解接口

建议把逆解、正解、返回值解析合成一层：

- 逆解请求串生成
- 逆解结果转 `JointPositions`
- 正解请求串生成
- 正解结果转 `Pose`

当前 `InverseKinematicsUtils` 已经具备一部分能力，适合直接升级为这一层的基础实现。

建议未来对外暴露成：

- `RobotKinematicsApi`

### 3. 摆动参数接口

摆动参数建议拆成“通用参数 + 类型参数”两层：

通用参数：

- `comments`
- `amplitude`
- `frequency`

类型参数：

- Trapezoid: `leftStopTime`、`rightStopTime`、`blendRadius`
- Crescent: `leftStopTime`、`rightStopTime`、`depth`
- Circle: `width`、`orientation`
- Zigzag: `leftStopTime`、`rightStopTime`、`angle`、`centerStayTime`

建议把 UI 侧的“填参逻辑”和持久化侧的“序列化逻辑”都对齐到同一套参数对象，不要在多个面板里重复 `switch(type)`。

建议未来对外暴露成：

- `OscillationParamApi`
- 或者 `SwingParamBinder`

### 4. 姿态转换接口

建议把欧拉角、四元数、位姿、变换矩阵的转换统一起来：

- `Pose <-> Transform3D`
- `Pose <-> RFrame`
- `Euler <-> Quaternion`
- `Euler <-> AxisAngle`
- `world/local frame` 转换

当前 `Math3D` 已经包含大量帧与欧拉角转换函数，适合作为底层实现继续收拢。

建议未来对外暴露成：

- `RobotRotationApi`
- 或者 `RobotTransformApi`

## 推荐的落点

如果后面真要改代码，建议按这个顺序收：

1. 先收运动脚本接口
2. 再收逆解与姿态转换
3. 最后收摆动参数填充

这样可以先把最容易重复、最容易出错的脚本拼接统一掉。

## 一句话总结

这次归并的核心不是改业务逻辑，而是把“会反复被用到的能力”收成少数公共入口，让上层节点只负责传参，不再自己拼脚本、拼坐标、拼参数。
