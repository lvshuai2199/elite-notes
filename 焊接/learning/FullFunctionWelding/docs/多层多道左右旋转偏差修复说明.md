# 多层多道「左右旋转」大角度偏差修复说明

## 1. 问题现象

在多层多道（多层多道）焊接计算中，即使起焊点、Z 参考点、Y 参考点都通过示教器正确输入，
当焊枪倾角（工作角）较大时，**左右旋转（leftRightRotation / 左右旋转）**产生的姿态仍会出现较大偏差，
且角度越大偏差越明显。

## 2. 根因

`leftRightRotation`（左右旋转）被**施加了两次**，而且两次使用的**旋转轴不一致**：

| 位置 | 施加方式 | 旋转轴 | 是否正确 |
| --- | --- | --- | --- |
| `MultiPassPoseTransformer.applyRotationOnly` | `setRy(leftRightRotation)` 后 `PoseCalcUtils.mul` | 工具**局部 Y 轴** | ❌ 错误 |
| `MultiPassAngleResolver.mergeAngleData` | `workAngle += leftRightRotation` | **运行方向**（工作角） | ✅ 正确 |

「左右旋转」的正确语义是**绕运行方向旋转**，即改变工作角。
但 `applyRotationOnly` 却把它当成「绕工具自身 Y 轴」的 Ry 旋转。

两者叠加后：

1. `applyRotationOnly` 先绕工具局部 Y 轴转了一次（轴错了）；
2. `mergeAngleData` + `pointOffset` 又绕运行方向转了一次（轴对了，但输入姿态已被第一次 Ry 污染）。

旋转被双重施加，且第一次的旋转轴在焊枪大倾角时与运行方向严重不重合，于是角度越大、偏差越大。

### 为什么「工具局部 Y 轴」在大角度下会错？

示教姿态为 `rot[Rx=40.53°, Ry≈0, Rz=90°]` 时，按本库 RPY 约定（R = Rz·Ry·Rx）展开，工具三轴在世界系为：

- 工具 X 轴 = `(0, 1, 0)` —— 恰好等于运行方向
- 工具 Z 轴（枪轴）= `(0.6496, 0, 0.7602)` —— 枪相对竖直方向侧倾 40.53°
- 工具 Y 轴 = `(-0.7602, 0, 0.6496)` —— **跟运行方向 `(0,1,0)` 差了近 90°**

因此「绕工具 Y 轴」转 ≠「绕运行方向」转，两者在焊枪带倾角时完全不是一回事。

| 文件 | 类 / 方法 | 作用 |
| --- | --- | --- |

| `impl/task/multipass/MultiPassAngleResolver.java` | `mergeAngleData` | ✅ 把左右旋转加到工作角 |
| `impl/task/multipass/MultiPassAngleResolver.java` | `applyLineAngles` / `applyCircleAngles` | 调用 `pointOffset` 重建姿态 |

## 4. 修改内容

**只改一处**：`MultiPassPoseTransformer.applyRotationOnly`。

修改前：

```java
public static Pose applyRotationOnly(Pose source, MultiPassWeldBead bead) {
    if (source == null || bead == null) {
        return source;
    }
    Pose basePose = copyPose(source);
    Pose offsetPose = PoseUtils.newPose();
    offsetPose.getRotation().setRy(parseNumber(bead.getLeftRightRotation()), Angle.Unit.DEG);
    return PoseCalcUtils.mul(basePose, offsetPose);
}
```

修改后：

```java
public static Pose applyRotationOnly(Pose source, MultiPassWeldBead bead) {
    if (source == null || bead == null) {
        return source;
    }
    // 左右旋转(leftRightRotation)不在这里按工具局部 Ry 施加：
    // 它的正确语义是绕“运行方向”旋转（即工作角），统一由
    // MultiPassAngleResolver.mergeAngleData + AngleTransUtils.pointOffset 处理。
    // 若这里再施加一次 Ry，会在工具局部 Y 轴上旋转（大角度下该轴与运行方向严重不重合），
    // 并且会与工作角路径叠加，导致左右旋转被双重施加、角度越大偏差越大。
    return copyPose(source);
}
```

即：`storeOverrides` 存 override 时**只保留位置偏移，不再改动姿态**，
把姿态旋转统一交给工作角路径（`mergeAngleData` + `pointOffset`）一次性完成。

## 5. 正确实现原理（数据流）

### 5.1 位置偏移（不受本次修改影响，原逻辑正确）

`prepareOverrides` 构建工件坐标系（原点 + 运行方向 X + Z 参考方向），
`MultiPathSection.offsetSectionPoints` 做位置偏移：

- 左右偏移方向：`offsetDir = frameZ × lineDir`（同时垂直于运行方向和 Z 参考方向）
- 上下偏移方向：`frameZ`（Z 参考方向）

### 5.2 姿态旋转（左右旋转的正确路径）

当 `leftRightRotation ≠ 0` 时：

1. `MultiPassAngleResolver.resolveLineAngleData` 从**原始示教姿态**算出工作角 `workAngle`、前进角 `forwardAngle`；
2. `mergeAngleData` 把左右旋转加到工作角：`workAngle += leftRightRotation`；
3. `AngleTransUtils.pointOffset` 绕运行方向按工作角/前进角重建枪姿态：
   - `zero_vec = forward × frameZ`（工作角 0° 参考方向）
   - 绕 `forward` 转 `workAngle` 得到工作平面向量
   - 再绕工作平面旋转轴转 `forwardAngle` 得到新的枪轴 Z
   - 用新 Z 与原始 X 轴重建坐标系

整个旋转只绕运行方向做一次，不再有工具局部 Ry 的叠加。

## 6. 验证结果

修复后实测（`leftRightRotation = 30`）：

| 量 | 值 |
| --- | --- |
| 示教姿态 | `rot[40.53°, 0, 90°]` |
| 原始工作角 | `-49.47°`（由 Rx=40.53° 反推：工作角 = Rx − 90°） |
| 修正后工作角 | `-19.47°` = `-49.47° + 30°` |
| 修正后姿态 | `rot[70.53°, ≈0, 90°]` |

- Rx 由 `40.53° → 70.53°`，**正好 +30°**，等于 `leftRightRotation`；
- Ry 保持 `≈0`、Rz 保持 `90°`，没有被带偏；
- 说明旋转只绕运行方向做了一次，数值正确。

## 7. 结论

问题根因是 `leftRightRotation` 在 `applyRotationOnly`（工具局部 Ry，轴错）与
`mergeAngleData`（工作角，轴对）中被**双重施加**。
修复方式是在 `applyRotationOnly` 中移除 Ry 施加，让姿态旋转统一由工作角路径完成。
修复后左右旋转只绕运行方向作用一次，焊枪大倾角下不再产生角度相关的偏差。
